## Xray

### 复现

生产入口监听 `::`，但 `lo` 没有 `::1` 地址，也没有对应本地路由。原检测客户端连接 `[::1]:443`，返回 `network is unreachable`，curl 退出码 `35`。将检测目标改为 `127.0.0.1:443` 后，同一现有 REALITY 入口成功完成 HTTPS 请求，返回 `warp=off`，与此前回滚后的直连配置一致。

`net.ipv6.conf.lo.disable_ipv6` 和 `all.disable_ipv6` 当时均为 `0`；没有将缺失地址归因于优化脚本。

### WARP

- 一次隔离检测中，默认 UDP 2408 未返回 WARP trace；备用 UDP 1701 成功。
- 使用 `162.159.192.1:1701` 的隔离实例，REALITY 与 Shadowsocks 入口均完成 HTTPS 请求并返回 `warp=on`。
- 随后重新从 GitHub 获取 `28bd652`，保留其自动端点选择逻辑再次检测；这次默认 UDP 2408 已恢复可用，两个入口均返回 `warp=on`，退出码 `0`。因此不能据此认定 2408 被永久封锁。
- 临时服务使用正式的 `xray` 用户；最终验证仅绑定本机随机端口。生产 Xray 的配置摘要和主进程 PID 在验证前后相同，测试实例及服务单元已清理。

这些结果证明当时 joysol 上的本机入口与 WARP HTTPS 出口可用，不证明手机客户端、公网端口、任意目标或持续 UDP 业务的可用性。生产配置仍是原来的直连配置，没有替换用户凭据。

## SSH socket

通过 GitHub `fb500ce` 在独立配置和 root 私有临时目录中创建测试 OpenSSH 服务，socket 只监听 `127.0.0.1`。测试使用临时主机密钥和客户端密钥，不修改生产用户的密钥：

1. 原端口 `40795` 建立真实公钥登录并保持会话。
2. 应用到新端口 `36515`，新旧端口均可公钥登录，原会话保留。
3. 从新端口的真实 SSH 连接执行确认，旧监听关闭，新端口可用，原会话保留。
4. 执行回滚，原配置逐字节恢复、旧端口恢复、新端口关闭，本次覆盖文件移除，原会话保留。
5. 测试单元及回滚计时器已清理；生产 `/etc/ssh/sshd_config` 摘要和 `ssh.service` 主进程 PID 未改变。

退出码 `0`。该测试使用 `--firewall keep`，不证明真实 UFW 改动；root 登录关闭和管理员创建新增功能另由隔离命令夹具及真实 sshd 配置解析检查，未在生产服务器创建管理员或关闭 root 登录。
