# Bilibili 增强

以 Loon 为主入口的 Bilibili 广告与推荐过滤插件，共享脚本无需下载第三方运行库。其他代理软件可通过支持 Loon 插件的转换工具转换配置；本仓库不提供单独的其他平台版本，转换后的语法、参数传递和脚本兼容性需要在目标软件验证。

## 功能与默认值

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| 过滤开屏广告 | 开启 | 清空已登记 JSON 开屏接口的 `list`、`show` 数组 |
| 过滤首页广告 | 开启 | 移除已识别广告卡片；横幅只移除广告项，保留其他内容 |
| 隐藏直播推荐 | 关闭 | 移除首页 `live`、`live_rcmd` 卡片 |
| 隐藏游戏推广 | 关闭 | 移除首页游戏卡片、导航游戏中心 |
| 隐藏会员购入口 | 关闭 | 隐藏导航中的会员购入口 |
| 隐藏发布入口 | 关闭 | 隐藏导航中的发布入口 |
| UP 主 UID 屏蔽名单 | 留空 | 多个数字 UID 用空格或逗号分隔，例如 `12345,67890` |
| 标题关键词屏蔽 | 留空 | 多个关键词用逗号分隔，例如 `抽奖,带货`；按字面包含匹配，英文不区分大小写 |
| 开发日志 | 关闭 | 本机保存有界诊断记录；页面导出和清空 |

UP 主和标题过滤仅作用于已覆盖首页接口。UID 必须能从卡片的 `args.up_id` 识别，不会按名称猜测归属。精简导航后仅重新排列已有数字 `pos` 字段，保留其他入口和未知字段。

## 安装与更新

在 Loon 中添加远程插件：

```text
https://raw.githubusercontent.com/teaoea/shell/main/plugins/Bilibili/BilibiliEnhance.plugin
```

1. 在 Loon 中添加插件，开启 MitM，并安装、信任 Loon 的 CA 证书。
2. 在插件参数页面设置所需开关，首次建议保留默认值。
3. 退出并重新打开 Bilibili，刷新首页。已有开屏缓存可能继续显示，不据此判断脚本是否执行。
4. 更新时同时刷新插件和 `BilibiliEnhance.js` 脚本缓存。不要同时启用其他匹配这些接口的 Bilibili 脚本，避免执行顺序冲突。

关闭插件即可停止修改后续响应；若只想关闭过滤并保留插件，把全部开关关闭、两项屏蔽名单清空。已经渲染的页面需重新加载。

## 覆盖范围和限制

广告和推荐过滤只匹配 `https://app.bilibili.com`（可带 `:443`）下的以下 GET JSON 响应：

- `/x/v2/splash/list`、`/x/v2/splash/show`
- `/x/v2/feed/index`、`/x/v2/feed/index/story`
- `/x/resource/show/tab`、`/x/resource/show/tab/v2`

广告识别使用明确的 `is_ad` 标志、非空对象 `ad_info` 以及已登记的广告卡片类型／跳转类型组合；横幅使用 `type=ad`。未知结构保留，错误码、异常 JSON、非文本正文、超过 2 MiB 的正文、含超出 JavaScript 安全整数范围的数字及未发生修改的响应原样放行，避免重写时损坏长数字 ID。脚本不保存账号、Cookie 或原始响应正文，也不发起额外网络请求。

新版 App 的部分首页、动态、评论、播放页面走 gRPC／Protobuf，本版不处理这些接口，因此不能承诺全量去广告。视频内部口播、UP 主自行嵌入的推广、动态广告和播放页广告也不在本版范围内。没有修改登录、会员、付费内容或地区限制，没有后台播放、画质解锁功能。

## 开发日志

1. 在 Loon 插件参数中打开“开发日志”，复现需要排查的操作。
2. 在浏览器访问 [Bilibili 本地日志页](http://bilibili-logs.invalid/)，查看开关状态、已保存条数与淘汰条数。此地址由插件在本机响应，不是公网服务。
3. 关闭“开发日志”停止采集，再点“导出日志”下载 `bilibili-development.log`。文件为逐行 JSON，便于后续开发分析；导出操作本身不改变开关。
4. 使用“清空已存日志”删除本机保存的记录。关闭日志不会自动删除已有记录，日志页在开关关闭时仍可访问。

日志最多保存最近 **300 条**，并将序列化存储控制在 **256 KiB 字符上限**以内；超出后淘汰最早记录。字段只包含 UTC 时间、登记接口路径或 `other_api` 类别、固定方法类别、HTTP 状态、处理结果、列表处理前后数量、移除数量、正文字符长度、白名单字段的类型，以及已登记卡片类别的计数。卡片统计最多扫描前 200 项、保留 20 种组合；横幅子项的删除不计入顶层列表移除数量。

**不记录**完整 URL、查询串、请求／响应头、Cookie、Authorization、access_key、token、sign、设备标识、UP 主 UID、标题、关键词名单、用户输入、接口错误消息、广告对象内容或原始正文。未知卡片类别统一标为 `other`，未知字段名也不保存。存储中的记录在展示／导出前再次按白名单筛选，页面的清空校验值不进入导出文件。日志未上传到 GitHub 或其他服务器。

日志覆盖 `app.bilibili.com` 的可被 Loon 解密的 HTTP 响应：已有 JSON 接口记录结构和处理结果，其他接口只记录元数据，**不额外读取二进制正文**。已登记的部分 RPC 路径可显示具体接口名，其余路径统一为 `other_api`，不会保存路径里的账号或其他动态值。没有新增其他 Bilibili 主机的 MitM 范围；`api.bilibili.com`、`grpc.biliapi.net`、媒体 CDN、QUIC、WebSocket 帧及未解密流量不在日志范围内。

持久化接口没有原子追加，多个响应并发时可能丢记录，日志不代表完整网络抓包。存储不可用时过滤继续执行，日志页返回存储不可用提示，避免覆盖已有数据。转换到其他平台后仍需验证本地页面与持久化接口是否兼容。

## 验证

在本目录运行 `npm test`，或使用可用的 Node.js 执行 `node --test tests/*.test.mjs`。测试使用合成响应验证过滤、开关、参数解析、异常放行、插件匹配范围、敏感信息不落盘／不导出、容量与存储故障；不能证明当前 Bilibili App 一定使用这些接口，也不能证明手机已加载脚本。

实机需要分别确认开屏接口命中、首页广告卡片清理、普通视频保留、可选过滤开关与导航可用性。如果未生效，应先确认接口是否为本版覆盖的 JSON 路径，再提供脱敏后的响应结构；请勿发送 Cookie、access_key 或账号凭据。

接口与字段参考：[app2smile 的 Bilibili JSON 脚本](https://github.com/app2smile/rules/blob/master/js/bilibili-json.js)。本插件独立实现，未内嵌上游脚本；公开字段参考不等于当前版本的实机证据。
